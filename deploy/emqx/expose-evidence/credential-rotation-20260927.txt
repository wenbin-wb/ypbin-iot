# 明文窗口内设备凭据轮换 + 「旧口令不可用」判据（按复核 R8 要求，2026-09-27）
#
# 理由：1883 是**明文** MQTT ⇒ 验收期间用过的设备口令**视为已暴露**。
#       "收回端口 / 上 TLS" 只能阻止**将来**的嗅探，**不能撤销已经发生的暴露** ⇒ 必须轮换。
#
# 做法与判据（凭据只比长度/指纹，明文不打印、不落仓库）：
#   1) 签发 C（version=31，pwlen=43，sha256 前 8 = 28da0e4c）
#      从**生产机经公网 1883** 连接 ⇒ CONNECTED（退出码 0）——确认 C 有效
#   2) 等 25s 过签发端 @Idempotent 窗口后，再签发 D（version=32，pwlen=43，sha256 前 8 = 7e14cc03）
#      ⚠️ 实测坑：不等窗口直接连点会拿到 `R.code=409`（"上一次签发/轮换刚完成，请稍后重试"），
#         此时响应里**没有**口令 ⇒ 若脚本不校验长度就会把**空口令**当新口令交付出去（本轮踩过一次）。
#   3) 判据：旧 C ⇒ AUTH_REFUSED（退出码 2）；新 D ⇒ CONNECTED（退出码 0）
#      ✅ 旧口令确实已被作废 ⇒ 轮换有效
#   4) 交付：D 落到中间件机 `/opt/emqx/ingress/device-password`（**600**，长度 43，
#      sha256 前 12 = 7e14cc030b45）——供交付给真设备/模拟器；**明文未进仓库、未进日志**。
#   5) 生产机上的临时 A/B/C/D 明文与探针已 shred 删除并回读确认无残留。
#
# 遗留：`/opt/emqx/ingress/device-password` 是**有意的交付文件**（不是残留），
#       但生产前必须随"收回 1883 / 关测试账号"一起清理。
